Engram Documentation

v0.3.0 · a transparent memory sidecar for local and cloud LLMs

Install

# the package (Python 3.11+)
pip install engram-proxy
# or run without installing:
uvx --from engram-proxy engram up

# the local models Engram uses for background work (~2 GB total)
ollama pull qwen3:1.7b qwen3-embedding:0.6b

Requirements: Ollama running locally (for retrieval embeddings and background summarization - required even when your chat model is in the cloud), Python 3.11+. Tested on macOS Apple Silicon; Linux should work identically.

Quickstart

engram up                      # proxy on :11435, forwarding to Ollama on :11434

# in another terminal: same ollama CLI, new port - that's the whole integration
export OLLAMA_HOST=127.0.0.1:11435
ollama run qwen3:1.7b

Tell the model a fact. Quit. Start a new session and ask about it obliquely - the answer can only come from memory. Watch what happened with engram why, or open the live brain view at 127.0.0.1:11435/engram/ui.

Memories form a few seconds after each exchange (background summarization waits for GPU idle), so a fact becomes recallable in the next session, not the same instant you say it.

Integrations

Stock Ollama CLI / any OpenAI-compatible client

export OLLAMA_HOST=127.0.0.1:11435        # ollama CLI
base_url = "http://127.0.0.1:11435/v1"    # OpenAI SDKs, Hermes Agent, etc.

OpenClaw

# OpenClaw mandates Ollama's native API - Engram speaks it byte-faithfully
{ "models": { "providers": {
  "engram": { "baseUrl": "http://127.0.0.1:11435", "api": "ollama" }
} } }

Anthropic-protocol clients (local memory for cloud models)

ENGRAM_ANTHROPIC_UPSTREAM=https://api.minimax.io engram up
# point the client's anthropic base_url at:
http://127.0.0.1:11435/anthropic

Auth headers pass through untouched. The whole Messages surface follows the cloud upstream (count_tokens, batches, prefixed /v1/models included).

Memory verbs (MCP)

Agents that can call tools get explicit memory verbs over the same store as the transparent proxy. Register engram mcp as a stdio MCP server in your agent framework.

toolteaches the agent to…
memory_searchalways check memory before answering about the user's past; include_silent shows superseded/forgotten history
memory_savepersist a stated fact instantly (no waiting for background formation)
memory_correctfix a wrong/outdated memory - supersedes (history kept, never re-injected), never overwrites
memory_editreword a garbled gist in place (for changed facts, use correct instead)
memory_pinmark permanently important: outranks everything, never decays, still supersedable
memory_forgetsilence (reversible) or, with hard=true, delete for privacy
memory_profileread (or refresh) the consolidated user profile
memory_recent · memory_statsnewest traces · store health

Architecture

client ──► engramd :11435 ──► upstream (Ollama :11434 / cloud)
             │  recall: hybrid search + ACT-R activation (~90ms, no LLM)
             │  inject: budgeted block, placement preserves prompt caches
             │  tee: response streams byte-verbatim; shadow copy → episode log
             └─ write-behind (GPU-idle only): summarize → embed → link → store
                     └── engram.db  (SQLite WAL: traces, episodes, links,
                                     schemas, FTS5, vectors, job queue)
  • Recall is pure arithmetic. One capped embedder call at most; hard deadline; any failure = uninjected passthrough. Memory is an enhancement, never a gate.
  • Admission before ranking. A trace must clear raw relevance thresholds (cosine, or literal token matches) before activation orders anything - so "inject nothing" is the default on unrelated turns, which is what protects small models from distractors.
  • Adaptive budgets. The upstream model is probed once: <4B params → 2 gists / 350 tokens; 4–14B → 4 / 1000; ≥14B and cloud → 6 / 2000.
  • Cache-preserving injection. Prompts over ~4k tokens get the block on the newest user message, leaving the cached prefix byte-identical - measured 90s → 2s per turn locally, and it preserves cloud providers' cache-read discounts.
  • Scales past personal stores. Below 50k memories dense search is a single exact matmul. Past it an IVF index (spherical k-means, pure numpy) bounds every query to a sixteenth of the store, lexical admission prunes tokens present in >2% of traces, and index rebuilds run on a background thread only when something changed - a rebuild that a write raced is discarded, never installed. Measured: 80ms p95 full recall at 100k, 85ms at 250k - still embed-bound. See BENCHMARKS.md.

Memory lifecycle

  • Formation is picky. Pure questions, smalltalk, and framework plumbing never become memories. Statements are summarized with user-fact primacy (exact names and values; assistant elaboration ignored) with a deterministic extractive fallback.
  • Use strengthens. Retrieval counts as re-presentation (the testing effect) at loop-safe weights, capped per session.
  • Corrections supersede. Update markers ("actually…", "changed to…") or conflicting values silence the stale trace and keep it on record.
  • Consolidation. During idle, user-stated memories distill into a profile schema (aggregate questions like "what do you know about me" inject it) and into topic schemas: clusters of related memories get one synthesized summary each, injected when a cue lands near the cluster. Both are single-level by design - schemas build from traces, never from previous schemas, so no compounding drift.
  • Forgetting is retrieval failure. Unpinned traces below the activation line past 30 days drift to silent - invisible to injection but never gone. A strong direct cue (cosine ≥ 0.45 when nothing active answers) resurrects a silent memory automatically, and memory_search include_silent reaches them explicitly. A lone unreinforced mention lives ~46 days.
  • The graph primes. Traces link temporally (6h co-allocation window), semantically, and on co-retrieval; what was recalled last turn makes its neighbors easier to recall this turn, with fan damping so hubs can't dominate.

Provenance & trust

Every memory records whose words it came from:

  • user - the human. Full strength, eligible for salience boosts (corrections, "important", names, deadlines).
  • observed:<name> - third parties relayed by a gateway (group chats a bot observes). Half-weighted, never salience-boosted (imperatives from strangers are the grammar of injection attacks), rendered as "(reported by X, unverified)", and structurally unable to supersede anything the user said.
  • system - agent-framework plumbing arriving as user-role turns. Never becomes memory.

Injected blocks are stripped before storage (Engram never re-summarizes its own output), byte-identical retries dedup at half weight, and ENGRAM_QUARANTINE can bar any source from injection entirely while staying searchable.

The observatory

Open /engram/ui: memories orbit a neural core at a radius set by their live activation - reinforced memories fall inward, decaying ones drift out, recalls flare ember, pinned traces wear a ring, silent and superseded history dims at the rim. Press / to search; click any mote for its full dossier (gist, β importance, access history, provenance). It polls the daemon every 4s and doubles as the debugging surface: if recall surprises you, look at the sky. Click the LAST RECALL readout (bottom right) to inspect the last injection in full: block, latency, mode, and scored candidates, each clickable through to its dossier. Linkable as /engram/ui#recall.

Selecting a memory keeps its hebbian web lit: ember filaments run to every linked trace while the dossier shows the gist, activation, importance, provenance, and pin state. Deep-linkable as /engram/ui#trace=<id>.

Hovering any mote shows its id, status, live activation, and title in place, and lights up its links; here the ember-ringed pinned trace with its web.

Day one and lived in. A fresh store is a lone core over empty orbits; every conversation after that grows the constellation - memories fall inward as they prove useful, links form between the ones recalled together, and the ones that stop mattering dim toward the rim instead of disappearing. The counters top right tell the story at a glance (demo data).

Cloud models

Both cloud protocols work, independently or together. Set ENGRAM_ANTHROPIC_UPSTREAM and point your client's Anthropic base_url at http://127.0.0.1:11435/anthropic, or set ENGRAM_OPENAI_UPSTREAM to any OpenAI-compatible provider (OpenRouter, DeepSeek, Groq, ...) and point the client's OpenAI base_url at http://127.0.0.1:11435/v1. Chat goes to the cloud; embeddings, summarization, and consolidation stay on local Ollama, so the only added cloud cost is the injected block (≤2000 tokens on the cloud tier, typically far less - around 1% of a real agent prompt). Your memory store never leaves your machine.

Troubleshooting

symptomcause / fix
address already in useanother engramd holds :11435 - pkill -f "engram up"
no memories formcheck engram stats queue depth; the summarizer waits ~30s of GPU idle. Missing qwen3:1.7b → extractive summaries (still correct, terser)
degraded_recalls climbingembed calls exceeding the 250ms cap (GPU contention) - recall degrades to lexical-only for those turns and recovers on its own
slow first turns through big agentshuge prompt prefill; subsequent turns should hit the prompt cache. If every turn is slow, something churns the prompt head upstream of Engram
model answers ignore injected memorysub-2B answering models fumble context they're given; the memory block is visible in engram why - verify retrieval vs answering separately, like engram eval does
backupsqlite3 ~/.engram/engram.db ".backup backup.db" - never bare cp (WAL)
